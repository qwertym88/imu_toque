# WBC 物理仿真试验：2026-11-08

本次修改以提交 `4885eb2` 的原型为基线，使用同一份 `retargeted_motion.npz` 和 MuJoCo XML。
未重新重定向、修改原始 support mask、放大脚底或提高力矩上限。环境为 `humanoid_sim`，MuJoCo 3.9.0。

## 修改内容

- 用已知接触序列构造 ZMP 名义路径，双支撑阶段提前转移载荷中心。每次计划支撑内的足端位置固定，
  不继承重定向支撑脚的水平漂移；实际落脚误差通过支撑位姿锚点修正。
- 利用常高度 LIP 的有界解反向计算 DCM，再正向计算一致的 COM 位置和速度；下层采用 DCM 状态反馈。
  预瞄器是解析参考生成器，不是新增的 MPC QP。WBC 仍按动力学/接触等式消元，只优化 12 维关节力矩。
- 将 ZMP 的软代价从齐次力矩误差改为 ZMP 比值的一阶线性化。增加与期望竖直加速度一致的合力目标，
  以及活动支撑脚合计 `0.2 mg` 的法向力下界；无物理支撑时不虚构该支撑力。
- 在预期触地前降低、压平摆动脚，触地后让支撑脚对齐地面，不冻结首次脚边接触的倾斜姿态。
- 记录 MuJoCo 每个真实接触点的力，转换为足端世界坐标 wrench，与 QP 的 wrench/ZMP、加速度和力矩对照。
  wrench 的符号及力矩平移经过 `J^T lambda = qfrc_constraint` 数值检查。
- 修正 SO(3) 插值的乘法顺序、初始速度的播放倍率缩放，复用计算偏置的 MuJoCo 数据缓存。

主要默认值：`balance-mode=preview`、`momentum-weight=1000`、`load-transfer-time=2.0`（仿真秒）、
`dcm-gain=3`、`pelvis-xy-weight=1`、`pelvis-z-weight=10`、`zmp-weight=0.1`、`zmp-margin=0.005 m`。
摆动脚在预期触地前 `0.3 s` 开始落地修正，落地高度任务权重为 400。

## 对照结果

所有时间都指物理仿真的时间，不是程序运行耗时。参考时间约为仿真时间乘以 `speed`。

| 设置 | speed | 结果 |
|---|---:|---|
| 修改前原型 | 0.25 | 约 6.948 s 首次单支撑失稳，QP 不可行 |
| 新版，但 `--balance-mode retarget` | 0.25 | 约 7.002 s 失败；统一接触采样时刻后，仅提高权重仍不解决首个转换 |
| 新版默认参数，36 s 测试 | 0.25 | 完成 36.002 s，覆盖约 9 s 原参考，实际左右单支撑均建立 |
| 新版默认参数，延长到 50 s | 0.25 | 44.462 s 后续换脚时 QP 不可行，当时 base z 仍约 0.657 m |
| 新版默认参数，12 s 测试 | 1.0 | 9.402 s 后续转换失败，达到迭代上限且已失稳 |

新版前 36 s 的指标：

| 指标 | 数值 |
|---|---:|
| pelvis 最低高度 | 0.602 m |
| 最大基座倾斜角（竖直夹角） | 9.16° |
| 峰值力矩绝对值 | 74.45 Nm |
| 动力学/接触等式最大绝对残差 | 8.53e-13 |
| 硬不等式最大绝对残差（不同单位混合） | 1.54e-3，低于当前 2e-3 接受阈值 |
| 预测/实际总竖直力 RMSE | 9.38 N |
| 预测/实际 ZMP RMSE：x / y | 1.76 / 3.38 mm |
| 右脚计划单支撑 / 实际单脚承重 | 20.064 / 20.040 s |
| 左脚计划单支撑 / 实际单脚承重 | 3.268 / 3.220 s |

实际单脚承重按一脚 `Fz > 10 N`、另一脚不超过 10 N 统计，并只累计对应的计划单支撑帧。
首次右脚连续单支撑约 17.3 仿真秒，等价于原参考约 4.33 秒；表中的 20 s 是累计值。
不同速度会改变真实动力学需求，慢放成功不代表原速成功。

## 复现

在 `humanoid_sim` 环境，从仓库根目录运行：

```bash
python data/simulate_wbc.py --headless --speed 0.25 --duration 36 --output /tmp/wbc_preview.npz
python data/analyze_wbc.py /tmp/wbc_preview.npz --plot /tmp/wbc_preview.png
python -m unittest discover -s data -p 'test_wbc*.py' -v
```

查看窗口时去掉 `--headless`。延长验证可设置 `--duration 50`；原速可设置 `--speed 1 --duration 12`，
两者目前预期失败。用 `--balance-mode retarget` 做 COM 目标消融，其余默认设置保留。
每个新 trace 保存配置、运行是否完成和失败原因，便于区分“通过指定短段”和“整段步行成功”。
9 个数值/接触约定测试通过，覆盖 LIP 方程一致性、平移不变性、支撑多边形投影、SO(3) 插值、
ZMP 线性化、非零承重约束和实际接触 wrench 的广义力重建。

## 尚未解决

这仍是部分轨迹可运行的 WBC 原型，不能称为完整稳定步行控制器。预瞄层没有优化落脚位置/时间，也没有
显式考虑全身可达性、关节制动能力或真实接触点形成的承重区域；当前足底模型和摩擦近似也尚未升级。

角动量调节、预测关节限位和接触宽限保留为实验参数，均默认关闭。本轮测试未显示这些选项能一致提升表现：
原速角动量权重 100/1000 均未完成 14 s；0.1 s 关节限位预测在约 2.134 s 触发原坐标残差拒绝。
不能通过放宽求解接受阈值把它们标为成功。

下一步应针对 44.5 s 附近的换脚做局部检查：新脚触地时的位姿与接触点、可实现 wrench、髋/踝关节余量、
COM/DCM 状态和规划落脚误差。先处理这个固定失败窗口，再评估是否需要有限调整落脚点或接触时序。
