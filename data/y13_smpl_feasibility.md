# y13 下肢 IMU 数据与 SMPL 的绑定及转换可行性

评估对象：`data/y13_level_walking_3_8_trial01.h5` 及 `data/h5_info.md`。
检查日期：2026-11-11。下述测量统计来自 H5 本身；标注为假设的内容没有在文件中得到确认。
后续补充检查了新实验者的 `y13_MVN_3_8_01.xlsx`，结果见“新增 Xsens 参考记录”；
更正（2026-11-11）：用户确认新 Xsens 与旧数据来自不同实验者。旧 H5/SMPL 路线暂不参与当前开发；当前工作仅拟合新 Xsens 到 MuJoCo，见 `docs/y13_xsens_walk.md`。

## 判断

这套七 IMU 布局可以在解剖层面绑定到 SMPL 的骨盆和双侧髋、膝、踝旋转链。
在完成时间对齐、传感器到骨段的旋转标定和姿态质量修复后，可以构建由下肢测量驱动的
SMPL 参数序列。当前文件尚不足以直接得到经过验证的 SMPL 下肢姿态，更不能唯一确定
全身动作、个体体型和世界空间中的根节点轨迹。

应区分三个结果：

| 目标 | 本次判断 |
|---|---|
| 传感器到标准关节的解剖对应关系 | 可以，已写入 JSON 的 `sensor_binding` |
| 有物理意义的下肢 SMPL 姿态序列 | 有条件可行，需补齐标定并处理下述姿态异常 |
| 仅由该文件还原真实全身姿态、体型及位移 | 不可唯一确定，需要额外测量或明确的先验 |

本次没有生成以默认值冒充实测值的 SMPL 动作文件。JSON 中的标定旋转为 `null`，
状态为 `anatomical_binding_only_calibration_required`；其中不包含可直接播放的 SMPL 姿态。

## H5 中实际包含什么

有 `imu/01` 至 `imu/07` 七组数据，每组包含 `data: (N, 10)` 和 `timestamps: (N,)`。
另有 `metadata`，记录受试者、任务、速度参数、试次和采集程序时间。
没有骨段位置、关节中心、人体尺寸、身高、体重、SMPL 体型或视频姿态真值。
没有发现按钮 A/D 的逐事件时间序列，也没有明确标出的站立标定区间。

依据说明书和数值分布，分析采用以下**待固件/导出代码确认的列解释**：

```text
data[:, 0:4]   qw, qx, qy, qz
data[:, 4:7]   ax, ay, az    含重力，单位按 g 假设
data[:, 7:10]  gx, gy, gz    角速度，单位按 deg/s 假设
```

H5 数据集没有列名、单位、坐标约定属性。前四列近似单位四元数、随后三列在初始低运动区间
模长接近 1，支持上述解释，但不能替代采集代码确认。说明中“9 channels”与实际
`4+3+3=10` 个标量不一致；AAcc 在说明中指角速度，不是角加速度。

|---|---:|---:|---:|---:|

共有 289866 个样本，数据值和时间戳均有限；各路时间戳严格递增。

## 与标准骨架绑定

以下是标准 SMPL 的 0 基关节索引。对应的是“该骨段的姿态影响哪个近端关节”，
并非传感器直接测量关节角，也不表示 IMU 的物理安装点就是关节中心。

| IMU | 身体段 | 安装位置 | SMPL 关节 | 索引 | 父段传感器 |
|---|---|---|---|---:|---|
| 01 | 骨盆 | 骨盆 | pelvis | 0 | 无 |
| 02 | 右大腿 | 大腿外侧中部 | right_hip | 2 | 01 |
| 03 | 左大腿 | 大腿外侧中部 | left_hip | 1 | 01 |
| 04 | 右小腿 | 小腿近端，膝盖下方 | right_knee | 5 | 02 |
| 05 | 左小腿 | 小腿近端，膝盖下方 | left_knee | 4 | 03 |
| 06 | 右足 | 右脚脚背 | right_ankle | 8 | 04 |
| 07 | 左足 | 左脚脚背 | left_ankle | 7 | 05 |

小腿和足部安装位置已依据使用者补充说明更正：IMU 04/05 位于膝盖下方的小腿近端，
IMU 06/07 位于脚背。它们分别跟随小腿段和足段，用于推算膝、踝的父子段相对旋转。
这一区分也意味着不能将传感器安装点当作关节中心。安装位置的说明仍需结合完整轴向
或姿态标定来确定传感器到骨段的旋转。

足部传感器应约束踝关节之后的足段姿态。SMPL 的 `left_foot=10`、`right_foot=11`
位于踝关节的下游；单个刚性足部 IMU 无法再独立测出足趾相对足段的运动。

对应的两条运动链是：

```text
pelvis (0)
  ├─ left_hip (1) → left_knee (4) → left_ankle (7) → left_foot (10, 未独立测量)
  └─ right_hip (2) → right_knee (5) → right_ankle (8) → right_foot (11, 未独立测量)
```

这能约束骨盆全局朝向及六个下肢关节的局部旋转，前提是每个传感器刚性跟随对应骨段、
各路已同步且标定正确。上身、手臂及足趾等其余 17 个关节的局部旋转仍需默认姿态、
动作先验或其他传感器。SMPL 是参数化图形人体，不应将它的关节旋转直接等同于临床
关节角定义或当前 MuJoCo 模型的关节坐标。

## 不能跳过的转换环节

令 `R_ViSi(t)` 为设备给出的传感器到其导航参考系的旋转，采用主动旋转、列向量约定。
令 `A_i = R_WVi` 把该导航参考系对齐到共同世界系，`C_i = R_SiBi` 把目标骨架关节
参考轴映射到传感器轴。则：

```text
R_WBi(t) = A_i @ R_ViSi(t) @ C_i
R_local_i(t) = R_WBparent(t).T @ R_WBi(t)
```

骨盆使用其全局旋转；六个下肢关节使用父子之间的局部旋转。
最后将旋转矩阵转为以弧度表示的轴角，写入对应 SMPL 参数。
`C_i` 必须包含 SMPL 参考姿态/关节轴定义与实际安装方向的差异；不能简单对原始
四元数逐路转轴角后直接填表，也不能用 Euler 角相减计算关节旋转。

安装说明只给出每个部位一个轴的大致指向。只确定一个轴会留下绕该轴的自由度，
因此无法确定完整 `C_i`。应补齐完整安装示意、两条不共线的轴方向，或通过已知姿态与
功能动作进行标定。初始 2 秒七路角速度模长中位数约 1.53–2.06 deg/s，具有低运动特征；
没有标注证明这段一定是标准站姿或 T-pose。

若共同导航参考系已确定，可在已知参考姿态 `R_WBi_ref` 下计算：

```text
C_i = (A_i @ R_ViSi(t0)).T @ R_WBi_ref
```

若七个设备分别初始化航向，必须另外解决它们之间的参考系关系；一次静态姿态不能
无条件同时分离未知参考系差异和未知安装旋转。共同的绝对航向可按可视化需要选择，
但各段相对航向及其随时间的漂移必须控制。H5 没有磁场流，无法仅据此重跑带磁力计的融合。

## 本文件发现的主要障碍

### 1. 原始姿态存在大幅不连续

表中旋转差通过相邻旋转矩阵的 SO(3) 相对旋转角计算，已避免把 `q` 与 `-q` 的符号翻转
误当成姿态跳变。仅做四元数符号连续化不会消除这里列出的异常。

例如右足 IMU 06 在起点后约 150.728 秒的相邻样本间跳变 109.08°，
相邻陀螺仪模长约为 126°/s 和 155°/s。以标称 190 Hz 估算，一个周期的旋转约为
0.7–0.8°，远小于该跳变。主机时间戳有批量接收特征，不能用其瞬时间隔直接证明真实
采样角速度；但姿态与陀螺仪的严重不一致仍需要查明。

候选原因包括融合器校正/重置、四元数与惯性数据坐标定义不一致、分包组帧问题或
不同通道采样时刻不一致。仅凭 H5 无法锁定原因。应先检查 MCU 的轴映射、融合实现、
CAN 分包和主机组帧代码，再决定剔除、修复或重估姿态。若改用陀螺仪和加速度计重估，
仍需处理轴向、偏置、航向漂移及步行约束，不能认为重跑融合即可自动恢复准确姿态。

### 2. 姿态和加速度坐标尚未形成一致解释

假设四元数是 `wxyz`、主动传感器到世界旋转、共同世界系上方向为 `+Z`，将初始 2 秒的
加速度旋转到世界系，计算它与 `+Z` 的夹角中位数：

| IMU | 初始重力方向偏差 ° |
|---|---:|
| 01 | 0.49 |
| 02 | 41.37 |
| 03 | 26.49 |
| 04 | 30.38 |
| 05 | 26.33 |
| 06 | 1.51 |
| 07 | 0.86 |

这不是姿态真值误差，而是上述坐标解释的一致性诊断。它说明不能未经核实就让七路共用
同一套解释。需确认四元数的方向、各设备导航参考系，以及加速度/陀螺仪是否经过额外
轴交换或符号变换。传感器在身体上装歪，不能单独解释同一个传感器内部的四元数与
重力不一致；必要时需同时检查传感器偏置和初始条件。

### 3. 主机记录时间不足以证明精确同步

各路平均接收频率为 188.75–189.14 Hz，接近说明中的 190 Hz，但样本数不同。
约 44.5%–44.6% 的相邻时间间隔小于 1 ms，间隔中位数约 8.1 ms，提示批量轮询/接收行为。
各路首尾时间一致不等于内部每帧同时采样；不能按最短数组直接截断后堆叠。

应优先使用 MCU 采样计数或硬件时间戳进行对齐；若只能使用当前时间戳，公共时间轴上的
向量插值和四元数 SLERP 只能作为带同步不确定性的近似。姿态异常需在有效性检查后处理，
不宜先插值把大跳变扩散到邻近帧。

## 能输出哪些 SMPL 参数

经典 SMPL 包含根旋转及 23 个关节局部旋转，常用轴角表示共 72 维。
官方 `smplx` 实现的常用接口为：

| 参数 | 建议序列形状 | 本数据如何提供 |
|---|---|---|
| `global_orient` | `(T, 3)` | 标定后的骨盆全局旋转 |
| `body_pose` | `(T, 69)` | 填入六个下肢局部旋转，其余部分明确使用先验 |
| `betas` | 常用 `(10,)` 或广播为 `(T, 10)` | IMU 未测量体型，需人体测量/扫描拟合或声明使用模板 |
| `transl` | `(T, 3)` | IMU 未直接测量根位置，需额外估计或声明固定根位置 |

10 维 `betas` 是常用配置，不是 SMPL 体型空间的唯一维数。
可将 `global_orient` 与 `body_pose` 拼为 `(T, 72)` 的 `poses`，再用 NPZ 或 PKL
作为容器；“SMPL 格式”并不规定一个唯一文件扩展名。应同时保存帧率、坐标系、模型类型、
标定参数、实测关节 mask、先验补全部分和质量标记。

要渲染真实 SMPL 网格，还需对应的官方模型参数文件。当前仓库未包含 SMPL 模型，
已有的 MS-Human Locomotion MuJoCo 模型不能替代 SMPL 的模板、形状基和蒙皮参数。

跑台上的根位置尤其需要区分：3.8 km/h 是传送带速度，不是人体相对实验室持续前进的速度。
固定根位置可用于下肢原地动画，但必须注明该位置是假设。接触期足相对实验室会随跑带运动，
不能直接套用地面行走“支撑足世界速度为零”的约束。双积分含重力加速度也不能直接得到
可靠根轨迹；需要先验证坐标/单位、去除重力，并处理偏置、漂移和跑台接触运动。

### 它能怎样帮助自研设备

1. **建立下肢 SMPL 基线。** 使用 Xsens 的 Segment Orientation 和 Segment Position，
   完成 Xsens 骨架与 SMPL 参考骨架的对应、轴定义转换和拟合，可先建立一条下肢参考动作。
   它仍需要模型间的参考姿态/骨架转换；不能把 Xsens 的 ZXY/XZY Euler 关节角直接填入
   SMPL 轴角。上身与体型应继续标记为模型补全/拟合，根平移需单独处理。
2. **提供独立的步态统计参考。** 用户已更正 Xsens 与旧数据来自不同实验者，
   历史建议中的跨试次比较已暂停；不同实验者的记录不能当作个体内基线。这些比较包含真实的试次间动作差异，不能作为自研设备逐帧精度评价。
   不能将两条轨迹配对来拟合自研传感器的实际安装旋转，也不能直接复制 Xsens 自己的
   安装旋转。自研设备仍需依据自身完整轴向、已知姿态或另外采集的标定数据确定坐标变换。
3. **保留重新处理与结构化导出的入口。** 官方文档说明 MVN 是可在 Xsens 软件中重新
   处理的原生二进制格式。当前 XLSX 标为 Live，可先在支持相应功能的 MVN 软件中检查
   工程配置、校准结果及处理选项，再评估 HD 重处理，保留原文件并重新导出结果。
   MVNX 比 Excel 更适合后续程序读取，可包含骨架连接点、关节连接、参考姿态和逐帧时间等。
   重处理能否消除本记录中的具体异常，需要重新导出后验证。

若未来需要计算自研设备相对 Xsens 的逐帧姿态误差，或通过配对动作进行安装旋转拟合，
应另采两套设备同时佩戴、记录同一次动作的对应数据。当前这两份记录不满足该条件。

### 独立试次的时间解释

H5 实际起点为北京时间 14:06:12.450742。若 XLSX 的 Recorded Date 对应 Frame 0，
两者起点相差约 2.549 秒；Xsens 末帧会在 14:09:53.5875，晚于 H5 末帧约 2.001 秒。
这些仅是元数据推算。用户更正两份记录来自不同实验者后，这些数值不能解释为同一次
动作的同步偏移，不应据此平移时间轴进行逐帧比较。
即使互相关或动态时间规整能使两遍周期动作在形状上对齐，也不能把它们变成同步实测配对；
步态相位归一化只用于统计比较，不构成逐帧真值或安装标定依据。

按官方骨段位置的米制定义，这些不可能是跑台上受试者的真实逐帧位移；即使不依赖单位，
约 1 的站立骨盆高度和数百的逐帧水平跳变也已表明不连续。原因可能涉及参考系重置、
融合校正或导出处理，当前没有证据将其归因于某一种。
父子相对姿态在这些时刻也有残余跳变，例如右髋最大约 11.64°，因此不能只平移骨盆
消除位置跳变后就把全部关节姿态当作连续参考。

此外，连续区间内骨盆水平位置随跑台行走累积，整段末帧与首帧相距约 199.62 个导出
长度单位。该输出不是已验证的实验室固定跑台根轨迹，不能直接填入可信的 SMPL `transl`。
参考用途应先限定到质量经过验证的连续区间及下肢姿态；Xsens 也应被视为参考系统，
不能当作没有误差的绝对真值。

全量检查结果写入 `outputs/y13_xsens_reference_audit.json`。
已解析的三组数组保存在 `outputs/y13_xsens_reference_arrays.npz`，键包括 `frame`、
`frame_rate`、`segment_names`、`segment_quat_wxyz`、`sensor_quat_wxyz` 和
`segment_position_export_units`；NPZ 是分析缓存，不是 SMPL 文件，也未做坐标修复或同步。

## 推荐实施顺序

1. 核对采集端通道顺序、单位、四元数定义、完整轴向、CAN 分包与设备采样时钟。
2. 查明大跳变来源，确认各通道在同一传感器坐标系和相同采样时刻下的一致性。
3. 补录明确的站立参考姿态、朝向和髋屈伸/膝屈伸等功能标定，确定安装旋转及共同参考系。
4. 使用同步后的七路姿态，求骨盆全局旋转和六个下肢局部旋转，先检查静止段、左右侧、
   屈伸方向、连续性、膝轴及足段姿态；以视频或参考动捕验证后才报告精度。
5. 使用已声明的体型和上身先验生成 SMPL 下肢动画，再独立处理根平移与个体体型拟合。

如果希望利用学习模型补全全身，可参考 TransPose，但它的官方六 IMU 布局包含双前臂、
双小腿、头和骨盆，与本设备不同，不能只修改数组形状就使用原有模型。
需要针对本设备布局构建输入、合成/采集训练数据并验证泛化；补全得到的上身是推断结果。

## 复现

分析脚本：`tools/analyze_lower_body_imu.py`。
结果文件：`outputs/y13_smpl_feasibility.json`，其中保留完整统计与待标定的解剖绑定表。
脚本只读取原始 H5，输出诊断 JSON；不会执行姿态标定或伪造完整动作。

本次使用已安装 `h5py`、`numpy`、`scipy` 的本机 Conda base 环境执行：

```bash
/home/qwertym/anaconda3/bin/python tools/analyze_lower_body_imu.py
```
